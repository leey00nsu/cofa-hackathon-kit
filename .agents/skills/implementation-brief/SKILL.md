# 구현 이해와 제출 전 문답

이 스킬은 **과제풀이 단계**의 구현 완료·설명 준비용이다. 제출물 확정 후, 후속 서술형 중 또는 실제 서술형 문제의 답변 요청이면 AI 답변을 생성하지 않고 참가자가 직접 응시하도록 안내한다. 문서 열람이 허용된다고 가정하지 않는다.

## 모드 선택

“Q&A 리허설 시작” 요청이면 [리허설 절차](references/defense-rehearsal.md)를 읽어 적용하고 아래 복습 절차는 실행하지 않는다. 현재 구현과 [DEFENSE 기록](../../../docs/DEFENSE.md)을 조사해 **질문 5개만 먼저** 제시하고 참가자 답변을 기다린다. 답·힌트·LAST_REVIEW를 먼저 보여주거나 문답 생성만으로 이해를 확인했다고 기록하지 않는다. 평가와 학습 위치 안내는 실제 답변 뒤에 한다. 실제 AI 금지 평가와 제출 확정 후 AI 중단 규칙은 리허설 호출보다 우선한다.

일반적인 마무리·문답 준비 요청은 아래 **복습 모드**로 진행한다. 기존 6개 주제의 JSON 형식은 유지하며, 리허설의 다섯 관점이 실제 출제 수나 고정 문항이라고 주장하지 않는다.

재개 요청이나 맥락이 끊긴 문답 요청에서는 기존 `.hackathon/study/DEFENSE_REHEARSALS.md`의 답변 대기 5문항 회차부터 확인한다. 미응답 리허설 회차가 있고 참가자가 복습 전환을 명시하지 않았다면 리허설 절차로 질문·응답 상태를 복구한다. 일반 복습으로 바꿔 정답을 먼저 노출하지 않으며, 새 회차를 명시한 경우도 기존 실제 응답은 보존한다. 개발 중 단일 이해 질문의 대기는 5문항 회차와 구분한다.

## 개발 중 이해 확인

첫 자동 검증된 핵심 흐름과 중요한 결정 변화에는 메인이 별도 최종 복습 요청을 기다리지 않고 다음 유용한 대화에서 쉬운 설명과 질문 하나를 제안한다. 관련 R·실제 코드·실행과 D의 당시 이유를 대조해 입력→결과, 고객 기준과 자체 선택, 기록된 장단점·한계를 짧게 설명하고 다른 근거 있는 입력/선택에 대한 참가자의 직접 설명을 요청한다. 최종 UI 대기는 구분하며 모든 R의 Verified를 기다리지 않는다. 기록되지 않은 이유·대안·장단점은 만들지 않는다.

기존 답 숨김 리허설이 대기 중이면 해당 답·힌트를 먼저 설명하지 않고 그 모드를 유지한다. 개발 중의 단일 질문은 [DEFENSE의 개발 중 이해 확인](../../../docs/DEFENSE.md#개발-중-이해-확인)에 따라 같은 비공개 연습 파일의 별도 절에 실제 질문·응답·근거·피드백·대기/연기만 남긴다. 새 5문항 회차나 문답 파일을 자동 생성하지 않는다. 미응답·연기 중 독립 개발은 계속하고 최종 복습에서 남은 이해 확인을 알린다. 답변을 받으면 현재 근거를 대조하고 필요한 흐름만 보충 학습한다. 실제 AI 금지 평가·AI 중단 규칙은 항상 우선한다.

## 복습 모드

문제·필수 범위 설명은 기존 요구사항 정본의 문제/첫 흐름 요약을 출발점으로 삼고 실제 R·코드·검증과 대조한다. 첫 MVP와 최종 필수 범위를 구분하며 ‘고객 문제 → 필수 R → 실제 입력/처리/결과 → 결정 D·검증 V → 남은 한계’를 연결한다. 요약 문서의 완성이나 테스트 정상 종료만으로 필수 요구 완료를 주장하지 않는다. 새 PRD나 상태 표를 다시 만들지 않는다.

1. 남은 작업 시간을 확인하고 새 기능 확장을 멈춘다. 공식 과제 README, 프로젝트 AGENTS, `.hackathon/INTERVIEW_PROTOCOL.md`, 요구사항·결정·검증 기록과 `docs/DEFENSE.md`의 관련 흐름을 읽는다. 기존 요구사항 정본은 설치 결과 또는 `.hackathon/install.json`의 `requirements_path`를 따른다. 탐색 표와 실제 고객 확인 답변을 점검하고, 묻지 않은 영역·미확인 규칙·확인했지만 미구현인 요구를 구분한다. 중요한 미확인은 남은 시간에 맞는 질문으로 제안하고 답을 받지 못하면 한계로 남긴다. 실제 구현 파일과 핵심 데이터 흐름을 확인한다. DEFENSE도 원본 코드·실행 기록과 대조하고 없는 DB·API·아키텍처·성능·테스트·결정 이유를 만들지 않는다. 시간과 규정이 우선이다.
2. `.hackathon/AUTOMATED_TESTING.md`에 따라 현재 코드·수락 조건·환경에 유효한 최종 검사 근거가 있으면 재사용하고, 변경·실패·미검증 범위만 자동 검사·결함 수정·재실행한다. 설명 복습을 다시 요청했다는 이유로 전체 검사를 반복하지 않는다. `review-scope`로 미추적 파일까지 대상을 확인하고 `audit-requirements`로 장부 연결·최신성을 대조한다. 감사 PASS는 전체 요구 충족이나 의미적 정확성의 증명이 아니다. 실제 R별 최종 UI 확인 목록을 VERIFICATION에 모아 참가자에게 전달한다. 실제 결과 대기 중 문답 초안은 준비하되 관찰을 지어내지 않는다. UI 수정이 생기면 관련 자동 검사와 필요한 회귀·영향 UI를 재확인하고 최종 관찰을 문답에 반영한다. 실행 근거는 `python3 .hackathon/tools/kit.py check --workspace . --id <id> --requirement <R번호> -- <실제 명령 인자들>`로 기록한다. 실패·0건·전부 skip/todo·예상 실패만 있음·소스가 바뀐 근거를 통과로 설명하지 않는다. Browser는 참가자가 직접 확인한다.
3. `python3 .hackathon/tools/kit.py prepare-qa --workspace .`로 처음 문답 파일을 만들고, 이미 있으면 보존하며 갱신한다. 이 스킬의 [문답 규약](references/qa-contract.md)을 읽어 `.hackathon/study/qa.json`을 실제 답변으로 채운다. 실행 명령의 상세가 필요하면 `.hackathon/references/validation-tools.md`의 해당 절만 참조한다.
4. 핵심 6개 주제는 문제·우선순위, 구조·데이터 흐름, 업무 규칙·데이터 정확성, 검증·오류 복구, 대안·한계·변경 대응, AI 지시·판단이다. 각 주제당 핵심 질문 1개, 필요할 때 추가 질문 최대 6개다. 실제 서술형 문항과 일치한다고 주장하지 않는다.
5. 각 답변은 비개발자가 이해할 수 있는 말로 결론 → 사용자 입력부터 결과까지 실제 동작과 선택 이유 → 실제 확인 결과 → 한계 순서로 작성한다. 짧은 답변은 350자 이내, 상세 답변도 짧은 문장으로 쓴다. 함수명·파일·명령은 쉬운 설명 뒤 확인 근거로 붙이고 전문용어는 꼭 필요할 때 뜻을 풀어 쓴다. 중요한 결정은 D의 AI 제안·실제 결정 주체·채택/수정·당시 이유·결과를 대조한다. 실제 사건이 없는 참가자 판단/AI 실패를 만들지 않는다. 근거마다 실제 상대 경로·행 번호·그 행에 존재하는 짧은 인용을 확인한다. 쉬운 표현을 위해 실패나 미검증을 생략하지 말고, 일반 원리만 적거나 사후 추정을 당시 의도로 표현하지 않는다.
6. `render-qa`, `verify-qa` 명령으로 파일 지문·근거·출력 문서를 검증한다. 내용 검토 없이 지문만 바꾸지 않는다. 코드·요구사항·체크 기록이 바뀌면 관련 답변을 재검토한 뒤 `fingerprint`로 현재 지문을 받아 JSON에 반영하고 다시 렌더한다. 연결된 실행/관찰도 현재 적용 여부를 별도로 확인하며, `stale_check_ids`·`unverified_check_ids`·`unverified_log_ids`가 있으면 문서가 일치해도 종료 2다. 과거 실패를 회고 근거로 남길 수 있으나 현재 통과로 설명하지 않는다. 과거 기록을 지우거나 지문을 소급 수정하지 말고 현재 증명에 꼭 필요한 검사만 새 ID로 실행한다.
7. 참가자에게 `.hackathon/study/LAST_REVIEW.md`부터 읽게 하고, 핵심 6개를 본인 말로 설명하도록 안내한다. 개발 중 이미 받은 설명·응답·미확인·연기를 같은 비공개 연습 기록에서 확인하고 최종 구현에 영향받은 부분과 남은 이해 질문에 집중한다. 같은 유효한 질문을 이유 없이 반복하지 않는다. 미응답은 이해 확인 대기로 남기고 독립 작업을 이어간다. 실제 답변을 받은 뒤 정확성을 코드와 대조하고 부족한 이해를 설명한다. 문답 파일 생성이나 검사 통과를 참가자의 이해 완료로 기록하지 않는다. 참가자 복습과 직접 제출을 위한 시간을 남긴다.

완료 시 두 문서 경로, 실제 검사 결과, 미구현·미검증·한계를 알린다. 스크립트의 통과는 구조·일치 검사이며 답변의 의미적 정확성·참가자 이해·공식 채점 결과를 보장하지 않는다. 제출 버튼을 자동 조작하지 않는다. 확정 이후 AI를 멈춘다.

실제 답변에서 특정 흐름을 이해하지 못했다면 [답변 후 보충 학습](references/defense-rehearsal.md#보충-학습답변-후)만 필요한 범위에 적용한다. 같은 실제 입력의 값 변화와 코드 위치를 연결하고 다른 입력으로 다시 설명하게 한다. 첫 리허설 질문 전에 이 설명이나 정답을 보여주지 않는다.
