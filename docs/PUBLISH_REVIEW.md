# 공개 전 검토 범위

예정 저장소: `leey00nsu/cofa-hackathon-kit` / Public.

로컬 완성본을 검토한 뒤 사용자의 **최종 공개 승인**을 받은 경우에만 GitHub 저장소를 생성하고 Push한다. 저장소 이름 선택과 로컬 파일 작성은 외부 공개 승인으로 간주하지 않는다.

## 공개할 내용

- 준비물 README와 당일 시작·마무리 지시
- 여섯 영역의 인터뷰 확인 표·구현 진입 조건·구현 중 고객 재확인 절차
- 참가 안내를 반영한 운영 규칙 요약, 15분 체험·180분 작업 운영 예시
- 비어 있는 요구사항·결정·검증 양식과 로컬 Matt 설정
- Q→R→결정/구현→실행 결과 연결 규칙, 로컬 원문 Git 제외와 가상 형식 예시
- 실제 구현 기반 예상 문답 생성 스킬과 구조·근거·최신성 검사 도구
- 준비 도구의 회귀 테스트
- 출처·MIT 라이선스·고정 커밋·해시를 보존한 Matt 스킬 원본 38개

기본 설치는 핵심 Matt 10개와 자체 문답 스킬 1개다. `--matt all`을 선택하면 engineering/productivity의 Matt 27개와 자체 1개를 배치한다. 개인 전역 설정·플러그인을 수정하지 않는다. 기존 요구사항 장부를 재사용하고 정본 경로를 명시한다.

## 공개하지 않는 내용

참가자 PDF 원문·이미지·QR·응시 링크·신분 정보·개인 키·실제 과제·고객 답변·구현 답안·작업 로그·모의 작업 결과는 동봉하지 않는다. 실제 과제의 문답은 당일 제공된 작업 공간 안에서 작성하고 외부로 보내지 않는다.

`.gitignore`만 확인하지 않고 추적 파일·커밋 이력·실제 공개 ZIP 목록을 별도로 확인한다. 고객 원문뿐 아니라 요약·자료·생성 문답에도 공개 제한 정보가 있을 수 있다. 이미 커밋된 원문은 ignore나 파일 이동으로 제거되지 않는다.

## 검증 범위

설치 보존·충돌 차단·실제 명령 종료 코드 보존·잘못된 근거 차단·소스 변경 시 문답 무효화·문답 렌더 일치 검사를 테스트한다. 별도의 로컬 가상 CSV 과제로 정상·중복 입력 실행부터 핵심 6개 문답 생성·검사까지 연습한다.

장부 감사·R/수락 조건/참조 답변 지문·실행 당시 소스·0건/전부 skip·전체 실패 로그·수동 관찰의 진술 구분·미추적 파일 리뷰 범위·로컬 환경 조회도 가상 fixture와 격리된 임시 공간에서 검사한다. 다른 진행 중인 리허설에 설치하거나 실사용 테스트를 실행하지 않는다.

제공된 시험 플랫폼에서의 스킬 발견·승인 화면·모델 선택·Browser 연결은 15분 사전 체험에서 확인해야 한다. 실제 서술형 문항의 적중·공식 채점 결과·참가자의 이해를 보장하지 않는다.

공개 후에는 2차 결과 통지 전까지 저장소를 Public으로 유지한다. 현재 승인 대기 단계라면 외부 저장소 생성·Push를 수행하지 않는다.
