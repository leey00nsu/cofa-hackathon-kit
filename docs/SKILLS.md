# 필요한 순간의 Matt 스킬

원본은 고정 커밋 그대로 동봉한다. 환경이 원본의 도구 이름을 지원하지 않으면 해당 SKILL.md를 읽고 제공 Codex에서 가능한 절차로 수행한다. 스킬의 일반 절차가 대회 규정이나 과제 조건을 바꾸지 않는다.

시작할 때 이 문서를 한 번 읽고 단계 전환 때 관련 절을 적용한다. 기본 활성은 core Matt 10개 + implementation-brief다. 전체 원본은 보존하되 필요한 스킬만 사용한다. 기존 요구사항 정본 경로는 설치 결과/manifest를 따른다.

인터뷰 종료와 구현 전환은 [INTERVIEW_PROTOCOL.md](INTERVIEW_PROTOCOL.md)를 따른다. 스킬을 호출했다는 사실만으로 여섯 영역이 확인되거나 고객 검토를 받은 것으로 보지 않는다.

[EVIDENCE_TRACKING.md](EVIDENCE_TRACKING.md)의 프로젝트 AGENTS 규칙으로 Q→R→D/구현 파일→실제 검증을 연결한다. Matt 원본 SKILL.md는 수정하지 않는다. 모든 스킬을 매번 실행하지 않으며 실제 요구·변경 규모에 맞춰 선택한다.

| 상황 | 사용 |
| --- | --- |
| 고객 인터뷰 | `$grill-with-docs`의 질문 구조와 domain-modeling. 사실 확인은 열린 질문 1~3개씩 |
| 필요한 정보 확보 | 작은 수직 흐름 구현. `$implement`를 쓸 경우 시간·검증 범위를 분명히 지정 |
| 핵심 상태·계산 규칙 | `tdd`, `codebase-design`을 필요한 경계에만 사용 |
| 재현되는 오류 | `diagnosing-bugs`. 브라우저 자동 조작 대신 CLI·HTTP·참가자 수동 확인 |
| 최종 대조 | `code-review`의 요구사항·품질 관점. 작업 중인 미커밋 변경도 포함 |
| 제출 전 복습 | `$implementation-brief` |
| 세션 교체 | `$handoff`로 실제 파일·남은 질문·검증 상태 기록 |

## 대회 맥락에 적용할 조정

- 원본 grilling의 추천 답변·모든 결정 가지 해결·끝없는 확인을 고객 사실 발견에 강제하지 않는다. 참가자는 실제 요구사항을 가진 고객이 아니라 전달자다. 의사결정에 영향을 주는 불확실성을 우선 질문한다.
- `implement`를 시작할 때도 선택한 흐름을 바꾸는 중요한 미확인을 점검한다. 첫 작동 흐름 뒤와 제출 전 범위 확정 때는 고객에게 전달할 확인 질문을 제안하고 실제 답변을 기록한다.
- 업무 사실을 파일 시스템에서 알아낼 수 있다고 가정하지 않는다. 기술 환경은 Codex가 확인하고 업무 맥락은 실무자에게 질문한다.
- TDD의 확인 절차는 기존에 합의된 핵심 경계가 있으면 재사용한다. 사소한 변경마다 별도 인터뷰를 반복하지 않는다.
- `implement`의 commit은 작업 공간 내 로컬 기록일 뿐이다. Push·PR·외부 이슈 생성을 하지 않는다. 커밋 권한이 없거나 Git 작업 공간이 아니면 작업을 멈추는 필수조건으로 만들지 않는다.
- `code-review`의 기준점은 설치 시 기록한 base commit을 사용할 수 있다. 커밋 이후 diff만 검토해 미커밋 변경을 놓치지 않는다. 필수조건은 공식 README와 요구사항 장부다.
- `python3 .hackathon/tools/kit.py review-scope --workspace .`로 커밋·staged·unstaged·미추적 파일을 함께 열거한다. 삭제 파일도 살핀다. 원본의 HEAD 비교가 비어 있어도 새 파일이 있으면 직접 읽어 검토한다. Git이 없으면 확인 가능한 실제 파일과 한계를 기록한다.
- 제공 Codex 안에서 허용된 모델만 쓴다. 하위 에이전트의 모델·권한·자원 범위가 불명확하면 같은 세션에서 순차 검토한다. 하위 에이전트 수를 점수 목표로 삼지 않는다.
- 독립 검토자가 없으면 같은 세션의 재검토임을 분명히 한다. 첫 작동 흐름 뒤에는 참가자에게 고객 근거·선택 이유·실패 조건을 직접 설명하도록 제안한다. 미응답을 이해 확인으로 표시하지 않는다.
- 새 MCP·Plugin·외부 계정이 없어도 기본 흐름이 작동해야 한다. 자동 업데이트되는 플러그인 대신 동봉한 파일을 사용한다.

`setup-matt-pocock-skills`가 전제하는 로컬 트래커와 도메인 문서 위치는 설치기가 배치한다. 모든 티켓·PRD·ADR을 미리 만들지 않는다. 용어·중요한 결정이 생겼을 때 필요한 문서만 만든다.
