# 180분 작업 운영 예시

기준은 과제 시작 버튼을 누른 시점이다. 공식 작업 타이머와 14:00 종료 중 먼저 닿는 쪽을 우선한다.

| 경과 | 목표 |
| --- | --- |
| 0~8분 | 녹화 후 본인 확인·과제·실행 방법·필수 파일 확인 |
| 8~30분 | 여러 라운드로 여섯 영역 탐색, 우선순위·성공 기준과 중요한 미확인 점검 |
| 30~65분 | 확인된 첫 흐름 구현, 완성 후 고객에게 업무 흐름 확인 |
| 65~115분 | P0 확장, 새 규칙의 미확인 재질문, 핵심 검증 |
| 115~125분 | 고객 성공 기준으로 범위 확인, 누락·미확인·후순위 정리 |
| 125~145분 | 요구사항 대조·실패 수정·필수 실행 검증 |
| 145~158분 | 구현 기준 예상 문답 작성·근거 검사 |
| 158~168분 | 참가자 핵심 6개 복습·자기 설명 |
| 168~180분 | 저장·필수 경로·제출 미리보기·직접 확정 |

인터뷰는 구현 중에도 이어간다. 질문 개수를 채우지 않고, 매 답변의 근거와 남은 구현 영향을 확인한다. 위 구간은 권장치이며 응답 지연·과제 크기에 맞게 조정한다. 고객 확인을 제안한 것과 실제 답을 받은 것을 구분한다. 끝에 몰아 문답을 작성하지 않도록 중요한 결정·실패·검증 근거는 작업 중 남긴다.

개인 리허설의 시간·감독 조건은 해당 작업 공간의 연습 규칙을 따른다. 실제 시험이 아닌 연습에 공식 시험의 절대 종료 시각을 적용하지 않는다.

과제 제출 후 문항 준비 대기와 서술형 최대 30분이 이어진다. 10:00 시작 시 13:00 과제 종료 뒤 대기 약 5분이라면 약 13:35에 끝날 수 있지만 플랫폼 상태에 따라 달라진다. 남는 시간이 추가 작업·휴식으로 보장되지는 않는다.

서술형 5분: 질문 전제 확인 → 실제 구현에 대한 결론 → 데이터 흐름·근거 → 선택 이유·검증 → 한계를 본인 말로 입력한다. 답안은 다음 문항으로 이동하면 수정할 수 없다. 노트나 코드를 다시 볼 수 있다고 가정하지 않는다.
