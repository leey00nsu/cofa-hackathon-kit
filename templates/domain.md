# Domain docs

용어가 확정되면 저장소 루트 `GLOSSARY.md`를 사용한다. 중요한 선택은 기존 `.hackathon/DECISIONS.md`에 관련 R/D 번호·이유·대안으로 기록한다. 고객 확인과 자체 선택·미확인 가정을 구분한다. 요구사항과 수락 기준은 설치 manifest의 정본 경로(기본 `.hackathon/REQUIREMENTS.md`)를 따른다. 용어집을 명세나 임시 메모로 사용하지 않는다.

Matt `domain-modeling`의 ADR 기준과 형식을 유지한다. 되돌리기 어렵고, 맥락 없이 의외이며, 실제 대안 간 절충이 있었을 때만 ADR을 제안하고 필요한 시점에 만든다. 기존 ADR이 있으면 D 기록과 `docs/DEFENSE.md`에서 참조하며 결정을 중복 작성하지 않는다. DEFENSE는 실제 구현 흐름과 검증·한계의 짧은 색인이다.
