# 검증 기록

아직 과제별 검증 없음. V번호·관련 R번호·실제 테스트 이름/수동 절차·실행 명령·입력·기대 결과·관찰 결과·통과/실패·한계를 기록한다. 자동 체크는 `.hackathon/checks/`의 원본 실행 기록과 연결한다. 참가자의 Browser 수동 확인은 관찰자·실제 결과를 적고 자동 테스트와 구분한다. 미실행을 통과로 적지 않는다. 실패 수정 후에는 원래 절차를 재실행하고 기존 실패와 새 결과를 연결한다. 요구사항의 일부만 검사했으면 검증 범위를 명시하고 전체를 Verified로 올리지 않는다.

먼저 ‘무엇을 넣어 보았고, 어떤 결과가 나왔으며, 무엇은 아직 모르는지’를 쉬운 말로 요약한다. 정확한 명령·실행 ID·로그는 뒤에 근거로 붙이며 실제 원본 결과를 고쳐 쓰지 않는다.

`check --requirement <R번호>`의 JSON·전체 log와 실제 결과 셀의 `check:<ID>`를 연결한다. 실제로 전달받은 현재 코드의 수동 관찰은 `manual-check`로 보존하고 `manual:<ID>`로 참조한다. 소스·수락 조건·고객 답변 변경 뒤에는 해당 근거를 재검토한다. 테스트 0건·전부 skip은 NOT_RUN이며 미확인 요약은 UNVERIFIED다.

새 실행 기록은 전체 로그의 내용 지문도 보관한다. 장부 감사에서 로그 누락·변경을 확인하고, 지문이 없는 이전 기록은 원래 결과를 보존한 채 추가 보관 검사를 미확인으로 표시한다. `unverified_log_ids`가 남으면 근거 검증이 모두 끝났다고 설명하지 않는다. 수동 관찰에는 자동 실행 로그를 요구하지 않는다.

자료·계산 과제라면 한 줄/식별자/단위/기간/계산 대상의 근거와 실제로 확인한 결합 전후 건수·제외/반복·작은 독립 기대값을 해당 R/V에 연결한다. 모든 숫자·분야 지표를 일괄 검사하는 의무는 아니다.

## 중간 자동 검사

Codex가 실제 공개 인터페이스·API·저장·업무 흐름을 확인된 수락 조건으로 검사한다. 작은 수정은 관련 검사, 흐름 완성은 통합/회귀, 최종 UI 확인 전은 전체 관련 검사다. 자동 PASS 범위와 미검증 범위를 구분하며 기능마다 참가자의 클릭 검증을 기다리지 않는다.

## 최종 UI 확인 목록

아직 미작성·미실시. 기능 동결 뒤 실제 구현에 맞는 목록을 한 번에 전달한다. 행을 작성한 것만으로 관찰 완료가 아니며 참가자의 실제 결과만 기록한다. UI 수락 조건이 남은 R은 Implemented로 두고 독립 개발은 이어간다.

| 단계 | 관련 R | 실제 URL | 입력·행동 | 기대 관찰 | 실제 참가자 결과/관찰 ID |
| --- | --- | --- | --- | --- | --- |

수정이 생기면 관련 자동 검사와 영향 UI를 다시 확인한다. 고객의 업무 흐름 설명 피드백·참가자의 화면 조작·자동 HTTP 검사를 서로 구분한다.
