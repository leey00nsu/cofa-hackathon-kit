# 결정 기록

아직 과제별 결정 없음. 중요한 선택이 생길 때 D번호·관련 요구사항·당시 대안·선택 이유·한계·관련 파일을 짧게 기록한다. 뒤늦게 추정한 이유는 당시 기록과 구분한다.

어떤 불편이나 문제를 해결하려 했고 왜 이 방법을 골랐는지 비개발자가 이해할 말로 먼저 쓴다. 함수·파일·ADR은 뒤에 근거로 붙인다. 고객이 정한 기준과 개발 중 우리가 정한 방식을 구분한다.

중요한 D에만 **AI 제안 → 실제 결정 주체와 채택/수정/기각 → 당시 밝힌 이유 → 결과·검증 V/check**를 짧게 연결한다. 결정 주체는 실제로 선택한 참가자·고객·AI이며 단순히 답변을 전달하거나 AI가 자율 처리한 일을 참가자 선택으로 기록하지 않는다. 참가자가 AI를 고친 실제 사건이 있으면 ‘무엇을 보고 → 어떤 수정을 요청 → 무엇을 유지/변경/제외 → 재확인’도 같은 D에 담는다.

사건이 없으면 만들지 않고, 당시 이유를 듣지 못했으면 미기록으로 남긴다. 기존 R/Q/ADR/V를 참조하며 중요한 결정당 몇 문장으로 충분하다. 모든 기술 선택을 다시 승인받거나 별도 판단 장부를 추가하지 않는다. 민감한 원문은 Git 제외 영역에만 보관한다.
